# AGENTS.md

A Motoko library, published as the Mops package `bench`, for benchmarking Motoko code with `mops bench`.

## Build, test, and run

This project uses [Mops](https://mops.one) and requires `mops` and `dfx` installed.

- Install dependencies: `mops install`
- Run tests: `mops test`
- Run the example benchmark: `cd example && mops bench`

CI (`.github/workflows/pull_request_build.yml`) runs `mops test` and the example `mops bench`
on `ubuntu-22.04` with Node 22 and dfx `0.30.1`. `mops bench` starts a local dfx replica, so dfx
must be available for benchmarks.

## Layout

- `src/` — library source (`lib.mo`), imported in tests as `"../src"`.
- `test/` — `*.test.mo` files run by `mops test`.
- `example/` — a standalone Mops project with its own `mops.toml`; its `bench/*.bench.mo`
  files are executed by `mops bench` from within `example/`.

Consumers place benchmark code in `bench/*.bench.mo`; each file exports a `module` with a
`public func init() : Bench.Bench`.

## Conventions

- Toolchain versions are pinned in `mops.toml` under `[toolchain]` (`moc = "1.0.0"`,
  `wasmtime = "40.0.0"`); keep them in sync with `example/mops.toml`.
- The `.mops/` directory is generated by Mops and is gitignored — never hand-edit it.
- This package depends on `core`; packages used only in benchmarks belong in
  `[dev-dependencies]` in `mops.toml`.
- Bump the version in `mops.toml` and add an entry to `CHANGELOG.md` when releasing.
